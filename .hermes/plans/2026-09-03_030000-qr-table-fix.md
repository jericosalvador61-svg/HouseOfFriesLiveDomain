# QR Table System Fix — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Fix 8 bugs in the QR table ordering system — the root cause is that QR codes pass the **table number** instead of the **real database table ID**, causing mis-linking, duplicate table issues, race conditions, and security problems.

**Architecture:** The QR URL must carry the real `table_id` (DB primary key) + `table_type`. `occupy_table.php` must use atomic SQL updates with role checks. Backend validation must be strict. Frontend must escape HTML.

**Tech Stack:** PHP (PDO/MySQL), vanilla JS, Bootstrap 5, QRCode.js

---

## Bug Summary

| # | Bug | Severity | Root Cause |
|---|-----|----------|------------|
| 1 | QR sends table number instead of DB ID | **CRITICAL** | QR URL uses `?table_id=1` (number) not real DB PK |
| 2 | occupy_table.php ignores table_type | **HIGH** | Searches by `table_number` only, affects multiple rows |
| 3 | MAINTENANCE tables can be occupied by QR | **HIGH** | Status check doesn't block MAINTENANCE |
| 4 | Race condition on simultaneous scans | **MEDIUM** | Check-then-update not atomic |
| 5 | Duplicate active tables after delete/restore | **MEDIUM** | No unique constraint on (table_number, table_type) |
| 6 | Admin stats only count current page | **LOW** | `updateStats()` receives filtered array |
| 7 | HTML injection via unescaped values | **MEDIUM** | Direct concatenation of DB values into HTML |
| 8 | update_qr.php unused and unaudited | **LOW** | Endpoint exists but never called |

---

## Proposed Approach

1. **QR URL change**: `?table_id=1` → `?table_id=24&type=DINE_IN` (real DB ID + type)
2. **occupy_table.php rewrite**: Search by `table_id`, check `table_type`, block `MAINTENANCE`, atomic `UPDATE ... WHERE status = 'AVAILABLE'`
3. **place_order.php**: Already uses `table_id` correctly — just needs the real ID from the QR
4. **customer.js**: Parse `table_id` and `type` from URL params
5. **QR_Tables.js**: Generate QR with real `table_id` from DB, not table number
6. **add_table.php**: Validate `table_number` is numeric, strip HTML
7. **Frontend**: Escape all DB values before HTML insertion
8. **Stats**: Fix `updateStats()` to use full data, not paginated slice

### Task 2: Rewrite occupy_table.php — use table_id, check type, atomic, block MAINTENANCE

**Objective:** Fix all 4 bugs in occupy_table.php: use real table_id, check table_type, atomic update, block MAINTENANCE.

**Files:**
- Rewrite: `customer/occupy_table.php`

**Complete new code:**

```php
<?php
header('Content-Type: application/json');
require_once __DIR__ . '/../backend/db.php';
require_once __DIR__ . '/../backend/rate_limit.php';

hof_rate_limit('occupy_table', 20, 60);

$input = json_decode(file_get_contents('php://input'), true);
$tableId = $input['table_id'] ?? null;
$tableType = $input['type'] ?? null;

if (!$tableId) {
    echo json_encode(['status' => 'error', 'message' => 'Missing table ID']);
    exit;
}

try {
    // 1. Look up table by real DB ID — strict match
    $checkStmt = $pdo->prepare("
        SELECT table_id, table_number, table_type, status 
        FROM restaurant_table 
        WHERE table_id = ? AND is_deleted = 0
    ");
    $checkStmt->execute([$tableId]);
    $table = $checkStmt->fetch(PDO::FETCH_ASSOC);

    if (!$table) {
        echo json_encode(['status' => 'error', 'message' => 'Table not found']);
        exit;
    }

    // 2. Verify table type matches (DINE_IN QR only works for DINE_IN tables)
    if ($tableType && strtoupper($table['table_type']) !== strtoupper($tableType)) {
        echo json_encode(['status' => 'error', 'message' => 'Table type mismatch']);
        exit;
    }

    $currentStatus = strtoupper(trim($table['status']));

    // 3. Block OCCUPIED, RESERVED, and MAINTENANCE
    if (in_array($currentStatus, ['OCCUPIED', 'RESERVED', 'MAINTENANCE'], true)) {
        echo json_encode([
            'status' => 'occupied', 
            'message' => "This table is currently {$currentStatus}. Please choose another table."
        ]);
        exit;
    }

    // 4. Atomic update — only AVAILABLE rows (prevents race condition)
    $updateStmt = $pdo->prepare("
        UPDATE restaurant_table 
        SET status = 'OCCUPIED' 
        WHERE table_id = ? AND status = 'AVAILABLE' AND is_deleted = 0
    ");
    $updateStmt->execute([$tableId]);

    if ($updateStmt->rowCount() === 0) {
        // Someone else grabbed it between our check and update
        echo json_encode(['status' => 'occupied', 'message' => 'Table was just taken. Please try another.']);
        exit;
    }

    echo json_encode(['status' => 'success', 'message' => 'Table is now OCCUPIED']);

} catch (PDOException $e) {
    echo json_encode(['status' => 'error', 'message' => 'Server error. Please try again.']);
    error_log('occupy_table.php: ' . $e->getMessage());
}
?>
```

**Key changes:**
- `WHERE table_id = ?` — uses real DB primary key, not table number
- Checks `table_type` matches the QR's type parameter
- Blocks `MAINTENANCE` status (in addition to OCCUPIED and RESERVED)
- `UPDATE ... WHERE table_id = ? AND status = 'AVAILABLE'` — atomic update, no race condition
- Checks `rowCount()` — if 0 rows updated, another request already took it

function escapeHtml(str) {

    var div = document.createElement('div');

## Risks & Tradeoffs

| Risk | Mitigation |
|------|-----------|
| Existing QR codes printed and posted on tables are now invalid | Old QRs contain `?table_id=1` (table number). The fix changes to `?table_id=24` (real DB ID). **All existing QR codes must be regenerated and reprinted.** |
| Existing seed data has table_id == table_number (1→1, 2→2) | The system works with old data because they match. After adding/deleting tables, they diverge. The fix is needed BEFORE any table management happens. |
| Race condition fix changes behavior for failed occupies | The atomic update returns "table was just taken" instead of silently succeeding. This is correct behavior. |
| HTML escaping may break special characters in table names | Table numbers are integers — no risk. But future-proofing with escapeHtml() is best practice. |
